# WEBBP M4 — Frontend Correctness & Theme

Baseline `main`: `8ba1950b7ca539f2903c0f90384f79e6ed8a4528`

## Objective

M4 closes verified frontend correctness defects around theme state, Tailwind v4 dark-mode behavior, hero pointer motion, scroll subscriptions, reveal timing, and conflicting UI transforms.

This tranche intentionally does not claim full accessibility closure. Keyboard/focus/dialog completeness remains M5 scope.

## Verified defects before M4

### Theme split-brain

- `layout.jsx` bootstrapped first-time visitors to dark mode.
- `useTheme` independently selected the OS color scheme when no saved preference existed.
- the hook also maintained a `.dark` class while most custom styles used `data-theme`.
- Tailwind v4 was loaded CSS-first through `@import "tailwindcss"`, while `tailwind.config.js` still contained the legacy `darkMode: "class"` declaration without an explicit v4 config load.

This created multiple competing theme authorities.

### Hero motion did not render correctly

- `HeroCube` created `mounted=false` and never set it to true, so `cubeStyle` was never applied.
- `useHeroMotion` mutated refs in a perpetual requestAnimationFrame loop.
- ref mutation did not cause React to render `HeroVisual`, so calculated pointer/time transforms were not a reliable rendered state.
- the perpetual loop continued even when no pointer input changed.

### Duplicate scroll work

`Navbar` and the Hero independently called `useScrollProgress`, and each hook instance installed its own window scroll listener.

### Contact reveal bypass

The contact card correctly had an IntersectionObserver, but a second effect forced it visible after 300 ms regardless of intersection.

### Service card transform collision

`ServiceCard` wrote `element.style.transform` directly while Framer Motion also owned transforms through `whileHover`. The same component also contained the invalid `lleading-relaxed` class and an undefined `text-muted` utility.

### CSS animation debt

- `@keyframes fadeIn` existed twice.
- `.animate-float` existed twice, with the later rule always shadowing the earlier rule.
- Hero used `animate-fade-in` without an explicit project definition.
- HeroBackground passed `duration={1200}` to Framer Motion even though the API uses seconds.

## M4 changes

### Single theme authority

- Tailwind v4 dark variant is declared in CSS against `data-theme="dark"`.
- pre-hydration theme boot uses a valid saved preference, otherwise OS preference.
- `useTheme` is backed by `useSyncExternalStore` and reads/writes the same `data-theme` authority.
- system theme changes continue to apply until the user stores an explicit preference.
- legacy `.dark` synchronization is removed.
- the unused Tailwind v3-style JavaScript config is removed.
- stale Geist theme variables are removed; the actual Rajdhani font variable is exposed as the sans theme font.

### Correct render-driven hero motion

- pointer position is now React state updated at most once per animation frame in response to actual mouse movement.
- no perpetual animation-frame loop remains.
- `time.current` and `mouse.current` render dependencies are removed.
- `HeroCube` applies `cubeStyle` directly instead of using a never-opened mount gate.
- mobile/device detection uses `useSyncExternalStore` for hydration-safe media-query state.

### Shared scroll store

- scroll state now uses one module-level passive listener shared by subscribers.
- updates are requestAnimationFrame-throttled.
- the listener is removed when there are no subscribers.

### UI correctness cleanup

- contact reveal is controlled only by intersection.
- ServiceCard no longer writes a transform that competes with Framer Motion.
- service pointer tracking is limited to spotlight CSS variables.
- `lleading-relaxed` and undefined `text-muted` are corrected.
- duplicate fade/float rules are consolidated.
- `animate-fade-in` receives an explicit project rule.
- HeroBackground reveal duration is corrected to 1.2 seconds.
