# WEBBP M8 — Corporate Repositioning

Baseline `main`: `15b4d85b0a8075d2c3b3384df9153fdb6e18d221`

## Objective

M8 repositions the public WEBBP site from a generic services/portfolio presentation into a clearer Bakaran Project product-house narrative without inventing legal, commercial, partnership, or production-readiness claims.

The public information architecture becomes:

- Home
- Solutions
- Products
- About
- Contact
- Legal routes remain `/privacy` and `/terms`

## Positioning guardrails

Bakaran Project is described as a product engineering team / digital product and systems engineering initiative.

M8 does **not** claim that Bakaran Project is a registered legal entity or corporation. It does not publish unverified address, telephone, company registration, customer counts, revenue, partnership, SLA, production adoption, or performance claims.

Megadata or any other partnership is intentionally not published in this tranche because public partnership status is not part of the repository evidence gate.

## Brand typography

The original WEBBP visual character is retained with:

- Orbitron for brand and display headings;
- Rajdhani for body copy and interface text.

The fonts are self-hosted through Fontsource packages. M8 does not restore `next/font/google`, so the production build does not depend on Google Fonts network access.

## Solutions narrative

The previous six generic service cards are consolidated into three evidence-backed solution domains:

1. **Education Systems**
   - Bakaran Platform
   - HADIRA
   - KARSA
   - SmartLab

2. **Operational Platforms & Integration**
   - shared platform foundation
   - authorization and domain ownership
   - API/integration boundaries
   - entity mapping and reconciliation
   - audit-oriented adoption

3. **Smart Mobility & Edge**
   - SINGGAH
   - parking and entitlement boundaries
   - edge operation
   - ANPR R&D with explicit evidence gates

These are solution domains, not claims that every capability is production-complete.

Solution cards use equal-height row layout rather than a hardcoded fixed card height. Internal title, subtitle, summary, and CTA regions are aligned while expanded detail is allowed to grow naturally.

## Product portfolio

The product section remains source-of-truth driven. Existing statuses are preserved:

- Bakaran Platform — In Development
- HADIRA — In Development
- KARSA — Pre-production
- SmartLab — In Development
- SINGGAH — Prototype

M8 changes presentation and narrative, not maturity status.

Portfolio filtering now supports evidence-backed multi-tag taxonomy while preserving one primary category per product for display. Current filter tags cover Platform, Education, Integration, Shared Data, Attendance, PKL, Laboratory, Operations, Mobility, Edge, and AI / CV. Filter buttons expose matching product counts to make filter behavior easier to verify.

Project cards use a stable button hitbox. The hover lift is applied to an inner visual shell instead of moving the clickable button itself, preventing missed clicks while the hover transition is entering. Card headers remain fixed-height and card bodies use flex layout so technology chips align consistently at the bottom.

## Hero interaction

The BP hero cube interaction is restored using a semantic button instead of the earlier non-semantic clickable container. Mouse, keyboard Enter/Space, and focus-visible behavior are supported while toggling capability badges.

## About section

A new About section explains three operating principles:

- product-led development;
- explicit domain ownership;
- evidence before claims.

The section also explains that product maturity varies and that the website intentionally exposes development/pre-production/prototype status instead of flattening all products into a generic success story.

## Contact and footer

Contact language now starts from operational needs, boundaries, users, and source of truth rather than a generic project-sales CTA.

Footer navigation is aligned with the M8 information architecture and the three solution domains.

## Verification gate

Before merge:

```bash
npm ci
npm audit
npm audit --omit=dev
npm run verify
git diff --check
git status --short
```

Expected manual checks:

- navigation links scroll to Home, Solutions, Products, About, and Contact;
- three solution cards render with aligned heights on desktop and remain responsive on mobile;
- each solution card expands/collapses detail without breaking the row layout;
- portfolio filter counts match the visible projects for every multi-tag category;
- project cards open their modal on the first click without requiring the hover transition to settle;
- project-card hover/focus transitions remain smooth and keyboard accessible;
- About section is visible and readable in light/dark themes;
- Products retain their existing maturity/status labels;
- Contact CTA and footer links resolve correctly;
- `/privacy` and `/terms` remain available;
- exact-head Vercel preview succeeds.

No legal-entity, partnership, customer, production-adoption, performance, or revenue claim is introduced by M8.
