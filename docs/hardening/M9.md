## Objective

M9 hardens the existing public corporate/product website for a stable v1 release. It is not a redesign milestone and does not introduce CMS functionality.

The milestone focuses on:

- runtime and route reliability;
- production security headers;
- accessibility regression cleanup;
- public asset efficiency;
- production deployment evidence;
- release documentation and version decision.

## Implemented in the M9 branch

### Production security headers

`next.config.mjs` now applies repository-owned security headers to all routes:

- `Content-Security-Policy`;
- `Referrer-Policy: strict-origin-when-cross-origin`;
- `X-Content-Type-Options: nosniff`;
- `X-Frame-Options: DENY`;
- restrictive `Permissions-Policy` for camera, microphone, geolocation, and payment;
- `Strict-Transport-Security` without `includeSubDomains` or preload assumptions;
- `X-DNS-Prefetch-Control: off`.

The CSP is tailored to the current WEBBP implementation rather than copied from a generic template:

- scripts are same-origin; inline execution is allowed because the root layout contains the pre-hydration theme script and Next.js emits inline runtime data;
- `unsafe-eval` is allowed only in development for HMR/tooling;
- styles are same-origin with inline styles allowed because React/Framer Motion use inline style values;
- fonts are same-origin/data and are self-hosted through Fontsource;
- images are same-origin/data/blob;
- production network connections are same-origin only;
- objects are blocked;
- frame ancestors are blocked;
- production requests upgrade insecure subresources.

The header set still requires browser/runtime smoke testing before release.

### 404 behavior

A branded `src/app/not-found.jsx` page now provides:

- explicit 404 presentation;
- noindex/nofollow metadata;
- a clear route back to the homepage;
- the standard `#main-content` skip-link target.

### Accessibility regression cleanup

The root layout skip link targets `#main-content` on every public page. `/privacy` and `/terms` previously lacked that target; M9 adds `id="main-content"` and `tabIndex={-1}` to both legal-page `<main>` elements.

### Public asset efficiency

The navbar previously loaded `public/ico.svg` (~362 KB) for a 26×26 logo. M9 switches that navbar image to the existing `public/ico.png` (~43 KB), which is already used by the hero visual.

Root favicon metadata now uses `/favicon.ico` (~25 KB) instead of the large SVG. The SVG remains available for manifest and structured-data usage; those contracts are intentionally not changed without validated icon dimensions/behavior.

## Security audit observations

Repository search found no current `process.env` or `NEXT_PUBLIC_*` usage in application source, so no client-exposed application secret mechanism is currently present.

The current public experience has no application account/login surface and no website data-entry form. External public navigation is limited to explicit links such as the verified GitHub profile and email contact.

## Governance observation

At the M9 baseline:

- `main` is not branch-protected;
- repository rulesets endpoint returns an empty ruleset list;
- Vercel remains the observed remote deployment/status gate;
- local parity remains required by repository policy.

This is an explicit governance limitation and must remain documented unless enforcement is added through repository administration.

## Required verification before merge/release

At minimum:

```bash
npm ci
npm audit
npm audit --omit=dev
npm run verify
git diff --check
git status --short
```

Runtime smoke must additionally verify:

- homepage and legal routes;
- generated SEO/manifest routes;
- Open Graph/Twitter image routes;
- custom 404 response;
- CSP/security headers on a deployed build;
- no CSP breakage of theme, fonts, animation, navigation, or portfolio modal;
- desktop/mobile/theme/keyboard/reduced-motion regressions;
- exact-head Vercel success.

## Version decision

Do **not** set `1.0.0` merely because M9 implementation exists.

The version may move from `0.1.0` to `1.0.0` only after the v1 readiness checklist passes or any remaining item is explicitly documented and accepted as non-blocking.
