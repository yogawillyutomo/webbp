# WEBBP M6 — SEO & Discoverability

Baseline `main`: `8c8acdf7e3df2b0029dec1c5b55bdd885f77a303`

## Objective

M6 gives the public WEBBP site a consistent, crawlable, and shareable metadata surface using the native Next.js Metadata API and metadata file conventions.

This tranche does not claim search ranking improvements, Search Console ownership, or social-platform cache refreshes. It establishes the technical metadata required for those systems to understand and share the site correctly.

## Changes

### Centralized public SEO identity

`src/config/site.js` now owns:
- public site name;
- canonical site URL;
- canonical home title;
- public description;
- locale and language;
- verified public email and GitHub organization link.

No unverified phone, physical address, legal entity name, or social account is added.

### Root metadata

Root layout now provides:
- `metadataBase` from the canonical site URL;
- application name;
- reusable title template;
- evidence-led site description aligned with M3 positioning;
- creator/publisher label;
- favicon;
- manifest link;
- index/follow robots metadata including large image preview support.

The previous generic `Solusi Teknologi Terdepan` metadata copy is removed.

### Canonicals and social metadata

Canonical URLs are defined per indexable page:
- `/`
- `/privacy`
- `/terms`

Each page also receives route-correct Open Graph and Twitter title/description/URL metadata.

Canonical is intentionally not declared once at the root because child legal routes must not inherit `/` as their canonical URL.

### Open Graph and Twitter preview images

`opengraph-image.jsx` and `twitter-image.jsx` use Next.js `ImageResponse` to generate a 1200×630 branded PNG preview.

The social image uses only public, evidence-led BP positioning and does not introduce product maturity or performance claims.

### Crawl metadata routes

- `robots.js` allows public crawling and advertises the sitemap and canonical host;
- `sitemap.js` exposes the three current public routes;
- no false `lastModified` timestamp is generated on every deploy;
- route priorities/change frequencies are conservative hints rather than ranking claims.

### Web app manifest

`manifest.js` provides:
- Bakaran Project name/short name;
- description;
- `/` start URL;
- standalone display;
- background/theme colors;
- Indonesian language;
- existing SVG brand icon with `purpose: any`.

No maskable-icon claim is made because a dedicated verified maskable asset is not present.

### Structured data

Home page includes an Organization JSON-LD block with only verified public fields:
- name;
- URL;
- public logo URL;
- description;
- public email;
- verified GitHub organization as `sameAs`.

No address, telephone, founding date, legal registration, or partnership data is invented.

## Technical references

Implementation follows current Next.js file conventions for generated metadata routes and social images. These routes are expected to be handled and cached by Next.js according to framework defaults.

## Merge gate

Before merge:

```bash
npm ci
npm audit
npm audit --omit=dev
npm run verify
git diff --check
```

Expected runtime/build checks:
- 0 audit findings;
- 0 ESLint errors;
- production build succeeds;
- `/robots.txt` is generated;
- `/sitemap.xml` is generated;
- `/manifest.webmanifest` is generated;
- Open Graph/Twitter image routes build successfully;
- exact-head Vercel preview succeeds;
- working tree remains clean.

Manual browser checks before merge:
- home `<head>` has self-canonical;
- `/privacy` canonical points to `/privacy`;
- `/terms` canonical points to `/terms`;
- OG/Twitter title, description, and image tags are present;
- `/robots.txt`, `/sitemap.xml`, and `/manifest.webmanifest` return valid responses;
- JSON-LD is present on home and contains no unverified identity fields.
