# WEBBP M7 — Repository & Delivery Governance

Baseline `main`: `1f673d0726c32fa25652a0144944fb59e687442d`

## Objective

M7 reduces repository drift and makes the delivery process explicit, reviewable, and repeatable. It separates committed governance from repository-level GitHub settings so neither is overstated.

## Repository cleanup

Removed committed artifacts that are not source-of-truth inputs:

- `src/app.zip`
- `src/webbp.zip`
- generated `purged/globals.css`
- legacy `purgecss.config.js`
- unused Next.js starter assets (`file.svg`, `globe.svg`, `next.svg`, `vercel.svg`, `window.svg`)

The active BP assets (`ico.png`, `ico.svg`, and the app favicon) remain because they are used by the current site.

`.gitignore` now blocks future committed ZIP archives and `purged/` output.

## Contribution governance

Added:

- `CONTRIBUTING.md` with branch, merge-gate, evidence, dependency, secret, and security-reporting rules;
- `SECURITY.md` with a private vulnerability-reporting path;
- `.github/CODEOWNERS` with the current repository owner as the default reviewer;
- `.github/pull_request_template.md` with verification and public-claim checks;
- `.github/dependabot.yml` for weekly npm dependency update proposals.

## Delivery gate

The documented local merge gate is:

```bash
npm ci
npm audit
npm audit --omit=dev
npm run verify
git diff --check
git status --short
```

A Vercel preview/deployment is additional exact-head evidence. It does not replace the local dependency audit, lint, production build, whitespace check, or relevant manual browser verification.

## Dependency cleanup

The PurgeCSS runtime/configuration path is no longer used. Its config and generated output are removed in this tranche.

The `purgecss` devDependency must be removed with npm locally so `package.json` and `package-lock.json` are regenerated by the package manager in one operation. The lockfile must not be hand-edited to simulate an npm operation.

Required command on the M7 branch:

```bash
npm uninstall -D purgecss
```

The resulting `package.json` and `package-lock.json` changes must be committed to this branch before the final M7 verification gate.

## GitHub repository settings

At M7 baseline:

- `main` is not protected;
- repository rulesets are empty;
- there is no committed GitHub Actions workflow.

This tranche does **not** claim branch protection is enabled. The available repository connector does not expose a write action for branch protection/rulesets.

Protection should only be enabled with required checks that actually exist and are stable. Until a durable CI check is available, the merge policy remains explicit local verification plus exact-head Vercel evidence.

Recommended repository-level follow-up after the M7 code/config tranche is merged:

1. require pull requests before changes reach `main`;
2. block force pushes and branch deletion on `main`;
3. require conversation resolution;
4. require CODEOWNERS review if the collaboration model grows beyond the current owner;
5. add required status checks only after a reliable CI check exists.

## Actions / CI decision

No GitHub Actions workflow is introduced in this tranche. The repository currently has no Actions baseline, while prior project work has experienced GitHub Actions billing/availability constraints. Adding a required workflow before its execution path is proven would create a governance dependency that may block delivery without increasing assurance.

A later CI tranche can add a hosted or local-parity workflow once execution reliability is verified.

## Merge gate

Before M7 merge:

- remove `purgecss` through npm and commit the regenerated lockfile;
- `npm ci` passes;
- `npm audit` reports 0 vulnerabilities;
- `npm audit --omit=dev` reports 0 vulnerabilities;
- `npm run verify` passes;
- `git diff --check` passes;
- working tree is clean;
- exact-head Vercel succeeds;
- PR remains mergeable with no unexpected base drift.

Repository-level branch protection remains a separately verified follow-up and must not be reported as complete until GitHub itself shows it enabled.
