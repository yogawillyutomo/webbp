# WEBBP v1.1.0 Readiness Gate

## Purpose

This checklist records the evidence required to approve WEBBP `v1.1.0` as the next stable public release after `v1.0.0`.

The `v1.1.0` scope is intentionally limited to the public WEBBP surface. It does not turn WEBBP into an operational product platform or a CMS.

- Stable baseline tag: `v1.0.0`.
- M10 — Content Architecture & CMS Readiness merged through PR #18.
- M10 merge commit: `c7c108926ad3f27a0b7a05bca3d0e3d74645a5da`.

- Release branch: `release/v1.1.0`.

## 1. Public-surface change

`v1.1.0` is a minor release because it adds new backward-compatible public routes and discoverability without removing or breaking the established v1 public surface.

New public behavior since `v1.0.0`:

- canonical repository-backed content architecture;
- deterministic content validation in the standard verification gate;
- five evidence-backed product detail routes under `/products/[slug]`;
- product-specific metadata and canonical URLs;
- product routes included in sitemap;
- smoke coverage for every product route exposed by the sitemap;
- unknown product slugs use the established branded 404 experience.

## Accepted non-blocking limitations

### Repository governance

GitHub `main` remains without enforced branch protection/rulesets unless repository state changes before release. Release discipline therefore continues to rely on PR review discipline, exact-head verification, local parity, and deployment evidence.

### Performance measurement

No repeatable Lighthouse/Web Vitals score baseline is declared as a release criterion or public claim. This remains a measurement limitation, not evidence of a known blocking performance defect.

## Version decision

`1.1.0` is the approved release target for the completed M10 architecture work plus the M11 Product Detail Pages tranche because the release adds backward-compatible public routes and discoverability while preserving the existing v1 public contract.
