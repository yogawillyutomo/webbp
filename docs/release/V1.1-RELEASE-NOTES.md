# WEBBP v1.1.0 — Release Notes

## Status

WEBBP `v1.1.0` is approved as the next stable public release after `v1.0.0`.

This release expands the public website while preserving the product boundary: WEBBP remains the public corporate/product site for Bakaran Project, not the operational platform and not a CMS.

## What changed since v1.0.0

### M10 — Content Architecture & CMS Readiness

M10 moved public content ownership out of presentation-local files into a normalized repository-backed content layer.

The implemented boundary now provides:

- canonical public content models;
- server-side content repository/query access;
- normalized public props passed into Client Components;
- deterministic content validation as part of `npm run verify`;
- removal of duplicate product/solution data sources;
- vendor-neutral readiness for a future CMS without adopting one now.

M10 merged through PR #18 to:

`c7c108926ad3f27a0b7a05bca3d0e3d74645a5da`.

### M11 — Evidence-backed Product Detail Pages

M11 uses the M10 content architecture to add individually addressable public product pages.

New public routes:

- `/products/bakaran-platform`;
- `/products/hadira`;
- `/products/karsa`;
- `/products/smartlab`;
- `/products/singgah`.

Each page derives from canonical product content and exposes:

- explicit maturity/status;
- status detail and description;
- evidence-safe proof points;
- technology tags;
- related solution domains;
- canonical metadata.

The homepage portfolio modal now links to the canonical product detail page. Product routes are included in the sitemap, and the smoke gate discovers and verifies every exposed product detail route automatically.

`6df7388b6f3af2dd1a81ea45c7c9f207ae6d16c6`.

Post-merge Vercel for that exact commit completed successfully, and production smoke on `https://bakaranproject.com` was confirmed safe.

## Evidence-before-claims guardrails

`v1.1.0` does not introduce unsupported public claims.

Product maturity remains:

- Bakaran Platform — In Development;
- HADIRA — In Development;
- KARSA — Pre-production;
- SmartLab — In Development;
- SINGGAH — Prototype.

The release does not invent customer deployments, case-study outcomes, production adoption, revenue, SLA, benchmark, accuracy, or registered-company claims.

## CMS direction

WEBBP remains repository-driven in `v1.1.0`.

M10 created the adapter seam needed for a future headless CMS, but M12 remains conditional. CMS adoption is justified only if real editorial triggers emerge, such as persistent non-developer publishing, multi-editor review workflows, material content volume, scheduled publishing, or multi-channel content delivery.

No CMS provider is selected by this release.
